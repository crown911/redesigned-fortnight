# На связи — голосовая комната для двоих

Минимальный браузерный прототип: HTML + PeerJS + WebRTC. Сайт можно разместить на GitHub Pages.

## Что умеет
- Создать комнату и поделиться PeerJS-кодом.
- Подключиться к комнате друга.
- Передавать голос через WebRTC.
- Завершить звонок.

## Важно знать
- GitHub Pages хостит только статические файлы; собственного backend здесь нет.
- Для сигнализации используется публичный PeerServer Cloud (`0.peerjs.com`). Это удобно для первого теста, но не является гарантией постоянной доступности.
- Конфигурация по умолчанию использует STUN, но не TURN. Если сети обоих участников не позволяют установить прямое WebRTC-соединение, голос не подключится. Тогда потребуется TURN-релей.
- Код комнаты не является полноценной авторизацией. Передавайте его только другу.
- Страница должна открываться по HTTPS, иначе браузер может не разрешить микрофон.
- Оба пользователя должны разрешить доступ к микрофону и оставить вкладку открытой.

## Публикация на GitHub Pages
1. Создай новый репозиторий на GitHub, например `two-person-voice`.
2. Загрузи `index.html` в корень репозитория.
3. Открой **Settings → Pages**.
4. В разделе **Build and deployment** выбери **Deploy from a branch**, branch `main`, folder `/ (root)`, нажми **Save**.
5. Дождись публикации сайта и открой URL, показанный в разделе Pages.
6. Открой сайт в двух разных домашних сетях. Один нажимает **Создать комнату** и отправляет код второму; второй вводит код и нажимает **Подключиться**.

## Если не работает
- Проверь, что оба открыли опубликованный HTTPS-сайт и разрешили микрофон.
- Проверь, что код комнаты скопирован полностью и создатель комнаты не закрыл вкладку.
- Если сигнализация подключилась, но голос не пошёл, вероятна несовместимость NAT/firewall с прямым WebRTC. Следующий шаг — настроить TURN и добавить его ICE-конфигурацию.
